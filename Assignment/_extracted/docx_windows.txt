[114][Heading 2] 1.4 Scope and Limitations
[115][normal] The scope of the proposed system defines the functionalities and boundaries of VulnScan. The project focuses on the development of an intelligent web-based vulnerability assessment platform that assists users in identifying common web application security vulnerabilities, assessing associated risks, and providing appropriate remediation guidance. The scope of the project is divided into functional scope and project limitations.
[116][Heading 3] 1.4.1 Functional Scope
[117][normal] The proposed system includes the following functionalities:
[118][normal] User Authentication and Role-Based Access Control
[119][normal] The system supports secure user authentication using username and password.
[120][normal] Two user roles are provided: Administrator and Developer.
[121][normal] Administrators manage users, vulnerabilities, scan profiles, and system configurations, while Developers perform vulnerability assessments and view scan results.
[122][normal] Web Application Vulnerability Assessment
[123][normal] The system allows users to initiate vulnerability scans by specifying a target web application URL.
[124][normal] The scanner automatically crawls accessible web pages and performs vulnerability assessments based on the selected scan profile.
[125][normal] Configurable Scan Profiles
[126][normal] Administrators can configure predefined scan profiles consisting of selected vulnerability modules and scanning depth.
[127][normal] Developers select an appropriate scan profile before starting a vulnerability assessment.
[128][normal] Risk Assessment
[129][normal] The system evaluates detected vulnerabilities according to predefined severity levels and presents the results through an organized dashboard.
[130][normal] Risk assessment information assists users in prioritizing remediation efforts.
[131][normal] 
[132][normal] Vulnerability Knowledge Base
[133][normal] The system provides comprehensive information for each supported vulnerability, including descriptions, security impacts, remediation recommendations, secure coding practices, and OWASP references (OWASP Foundation, 2021).
[134][normal] Security Audit Logging
[135][normal] The system records significant security-related activities such as user authentication, scan execution, administrative actions, and report generation to improve accountability and traceability.
[136][Heading 3] 1.4.2 Project Limitations
[137][normal] The proposed system is developed within the constraints of an undergraduate Final Year Project. Therefore, several limitations are identified:
[138][normal] The system focuses on selected common web application vulnerabilities suitable for the project scope and does not aim to provide comprehensive penetration testing comparable to commercial security assessment platforms.
[139][normal] The system performs automated vulnerability assessment only and does not exploit or actively attack target systems beyond the implemented detection mechanisms.

[186][Heading 2] 2.1 Related Theories and Concepts
[187][Heading 3] 2.1.1 Web Application Security
[188][normal] Web application security refers to the practice of protecting web applications from unauthorized access, malicious attacks, data breaches, and other security threats throughout the software development lifecycle. Modern web applications frequently process sensitive information such as user credentials, financial records, healthcare information, and confidential business data, making them attractive targets for cybercriminals. Consequently, security must be incorporated into every phase of application development rather than being treated as a separate activity after deployment (OWASP Foundation, 2021).
[189][normal] Web application vulnerabilities commonly arise from insecure coding practices, improper authentication mechanisms, insufficient input validation, security misconfigurations, outdated software components, and inadequate access control. Attackers exploit these weaknesses to gain unauthorized access, execute malicious code, steal confidential information, or disrupt normal system operations. The increasing sophistication of cyberattacks has made web application security one of the most important domains within cybersecurity research and software engineering (OWASP Foundation, 2021).
[190][normal] To improve application security, organizations increasingly adopt secure software development practices, regular vulnerability assessments, security testing, and continuous monitoring throughout the software development lifecycle. International standards and security frameworks such as the OWASP Top 10 and the National Institute of Standards and Technology (NIST) Cybersecurity Framework provide widely accepted guidelines for identifying and mitigating common web application security risks (OWASP Foundation, 2021).
[191][Heading 3] 2.1.2 Vulnerability Assessment
[192][normal] Vulnerability assessment is a systematic process of identifying, analysing, and evaluating security weaknesses within an information system or web application before they can be exploited by attackers. Unlike penetration testing, which actively attempts to exploit identified vulnerabilities, vulnerability assessment primarily focuses on discovering and documenting security weaknesses to support risk mitigation and secure software development (Scambray et al., 2011). The objective of vulnerability assessment is to provide developers and security practitioners with sufficient information to prioritize remediation activities and strengthen the overall security posture of an application.
[193][normal] Modern vulnerability assessment commonly combines automated scanning techniques with manual verification to improve detection accuracy. Automated vulnerability scanners significantly reduce the time required to identify common security weaknesses such as SQL Injection, Cross-Site Scripting (XSS), insecure HTTP headers, broken authentication, and security misconfigurations. However, automated tools may also generate false positives and false negatives, making human verification an important component of comprehensive security assessment (OWASP Foundation, 2021).
[194][normal] Vulnerability assessment has become an essential activity within the Secure Software Development Lifecycle (SSDLC). Performing security assessments during software development enables vulnerabilities to be identified earlier, reducing remediation costs and minimizing the likelihood of security incidents after deployment. Consequently, organizations increasingly integrate automated vulnerability scanning into continuous integration and continuous deployment (CI/CD) pipelines as part of DevSecOps practices (NIST, 2020).

[424][Heading 2] 4.1 Architecture Design
[425][normal] 
[426][normal] Figure 4.1: Overall System Architecture of VulnScan
[427][normal] The overall architecture of VulnScan is designed using a layered architecture to separate system responsibilities into distinct layers, thereby improving maintainability, scalability, and modularity. As illustrated in Figure 4.1, the system consists of five primary layers: the Presentation Layer, API Layer, Business Logic Layer, Scanner Engine Layer, and Data Layer. Each layer performs a specific function while interacting with adjacent layers through well-defined interfaces, reducing coupling between system components and simplifying future maintenance (Pressman & Maxim, 2020).
[428][normal] The Presentation Layer provides separate interfaces for Developers and Administrators through a web application. Developers are able to initiate vulnerability scans, review scan results, and manage scan profiles, whereas Administrators perform system management tasks such as user administration, vulnerability management, and monitoring system activities. User requests are forwarded to the API Layer, where the Flask REST API processes incoming requests and coordinates communication between the user interface and the backend services.
[429][normal] The Business Logic Layer contains the core application modules responsible for implementing the business rules of the system. These modules include Authentication, Scan Management, Scan Profile Management, Vulnerability Management, and Audit Logging. The Business Logic Layer validates user requests, applies access control, manages application data, and coordinates interactions with the Scanner Engine.
[430][normal] The Scanner Engine Layer is responsible for performing vulnerability assessments on target web applications. It consists of a Web Crawler and multiple independent vulnerability detection modules, including SQL Injection, Cross-Site Scripting (XSS), and HTTP Security Header analysis. The modular design enables additional vulnerability detection modules, such as Cross-Site Request Forgery (CSRF), XML External Entity (XXE), Server-Side Request Forgery (SSRF), and Command Injection, to be incorporated in future versions without requiring significant modifications to the overall system architecture.
[431][normal] The Data Layer utilises Microsoft SQL Server to manage application data, including user accounts, scan information, vulnerability definitions, scan profiles, findings, discovered pages, and security audit logs. This layered architecture promotes separation of concerns, facilitates future system enhancements, and ensures that each system component can be developed, tested, and maintained independently.

[436][Heading 2] 4.2 Database Design
[437][normal] The database is designed to provide a structured and reliable repository for managing user information, scan configurations, vulnerability definitions, scan results, and system activities. Microsoft SQL Server was selected as the database management system because of its robustness, transactional reliability, advanced security features, and seamless integration with SQLAlchemy. These capabilities make it suitable for managing the relational data required by VulnScan while supporting future scalability and maintenance.
[438][normal] The database design follows the principles of relational database modelling and has been normalised to Third Normal Form (3NF) to minimise data redundancy and maintain data consistency. Related data are separated into individual entities, with relationships established through primary and foreign keys to preserve referential integrity. This approach improves data organisation, simplifies maintenance, and reduces the risk of update anomalies.
[439][normal] As illustrated in Figure 4.2, the VulnScan database consists of eight entities: User, Scan, ScanProfile, ProfileModule, Vulnerability, DiscoveredPage, Finding, and SecurityAuditLog. Each entity is responsible for storing a specific category of information required by the system. The relationships among these entities enable the system to manage vulnerability scanning activities, configurable scan profiles, modular vulnerability definitions, detected findings, discovered web pages, and security audit records while maintaining consistency across the database.
[440][normal] The User entity manages user accounts, authentication information, and user roles, providing the foundation for role-based access control. The Scan entity stores information relating to each vulnerability assessment session and acts as the central entity connecting scan profiles, discovered pages, and detected findings. During execution, the Web Crawler records discovered web pages in the DiscoveredPage entity, while identified vulnerabilities are stored within the Finding entity and linked to the corresponding vulnerability definitions maintained in the Vulnerability entity.
[441][normal] To improve flexibility and future scalability, VulnScan adopts a configurable scan profile mechanism through the ScanProfile and ProfileModule entities. Rather than hardcoding supported vulnerabilities within the application, administrators can configure which vulnerability detection modules belong to each scan profile. This modular approach allows future detection modules, such as Cross-Site Request Forgery (CSRF), XML External Entity (XXE), Server-Side Request Forgery (SSRF), and Command Injection, to be incorporated without redesigning the database structure.
[442][normal] Finally, the SecurityAuditLog entity records significant user and system activities throughout the application. Maintaining audit records enhances accountability, supports security monitoring, and facilitates future forensic analysis by preserving a history of important events performed within the system.

[450][Heading 2] 4.3 User Interface Design
[451][normal] The user interface of VulnScan is designed to provide a simple, consistent, and intuitive experience for both Developers and Administrators. The interface emphasises usability by presenting system functions in a clear and organised manner, allowing users to perform vulnerability scanning and system administration with minimal complexity. Consistent layouts, navigation menus, and interface components are adopted throughout the system to improve user experience and reduce the learning curve.
[452][normal] The system provides separate interfaces based on user roles. After successful authentication, Developers are redirected to the Developer Dashboard, where they can manage scan profiles, initiate vulnerability scans, monitor scan progress, and review previous scan results. Administrators are redirected to the Administrator Dashboard, which provides additional functions such as user management, vulnerability management, scan profile configuration, and security audit log monitoring. This separation ensures that users only have access to functions relevant to their assigned roles.
[453][normal] The Login Page serves as the entry point to the system by allowing registered users to authenticate using their credentials. Upon successful login, users are redirected to the appropriate dashboard according to their assigned role. If authentication fails, appropriate error messages are displayed to guide users while preventing unauthorised access.
[454][normal] The Scan Management Page enables developers to configure and execute vulnerability scans by specifying the target URL and selecting a predefined scan profile. After the scan is completed, the Scan Result Page presents the detected vulnerabilities together with their severity level, affected pages, supporting evidence, and recommended remediation. The Administrator Dashboard provides management functions for maintaining users, vulnerabilities, scan profiles, and security audit logs, allowing administrators to oversee the overall operation of the system.
[455][normal] Overall, the user interface design focuses on usability, consistency, and accessibility to ensure that both developers and administrators can efficiently perform their respective tasks while interacting with VulnScan.
