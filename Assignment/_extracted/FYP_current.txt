Abstract
Modern web applications have become essential platforms for delivering online services across various industries. However, their increasing complexity has also introduced numerous security vulnerabilities that may lead to unauthorized access, data breaches, and service disruption. Although many vulnerability assessment tools are available, existing solutions are often designed for experienced cybersecurity professionals and primarily focus on vulnerability detection while providing limited educational guidance and remediation support. This project proposes VulnScan, an Intelligent Web Application Vulnerability Assessment Platform with Risk Assessment and Remediation Knowledge Base, to provide an accessible and educational solution for identifying and understanding common web application security vulnerabilities. The proposed system enables developers to perform automated vulnerability assessments by scanning target web applications for selected vulnerabilities, including SQL Injection (SQL Injection), Cross-Site Scripting (XSS), and HTTP Security Header misconfigurations. In addition to vulnerability detection, the system incorporates configurable scan profiles, risk assessment, role-based access control, security audit logging, and an integrated knowledge base containing vulnerability descriptions, security impacts, secure coding practices, and remediation recommendations. The system adopts the Agile Software Development methodology, allowing iterative planning, design, implementation, testing, and continuous improvement throughout the project lifecycle. The system architecture follows a layered design consisting of the Presentation Layer, API Layer, Business Logic Layer, Scanner Engine Layer, and Data Layer to improve modularity, scalability, and maintainability. Database normalization and modular vulnerability management further support future system expansion. Functional and non-functional testing are conducted to verify that the implemented system satisfies the specified requirements and performs reliably under normal operating conditions. Overall, VulnScan demonstrates that integrating automated vulnerability assessment with educational resources, centralized management, and risk evaluation can improve both web application security and users' understanding of secure software development. The proposed platform provides a practical and scalable foundation for future enhancement through additional vulnerability detection modules and advanced security analysis capabilities.

<Heading 2>1.1 Background and Context
<Heading 3>1.1.1 Cybersecurity
The rapid growth of digital technologies has transformed the way organizations, businesses, educational institutions, and government agencies deliver services through web applications. Online platforms are now widely used for banking, healthcare, education, e-commerce, and cloud-based services, enabling users to access information and perform transactions conveniently from anywhere with an Internet connection. As web applications continue to store and process sensitive information such as personal records, financial data, authentication credentials, and confidential business information, ensuring the security of these applications has become one of the most critical concerns in modern cybersecurity (OWASP Foundation, 2021; NIST, 2020).
<Heading 3>1.1.2 Web Applications
Despite significant advancements in software development practices, web applications remain one of the most frequently targeted attack surfaces by cybercriminals. Security vulnerabilities introduced during software development, insecure configurations, outdated software components, and improper input validation expose web applications to numerous cyberattacks. Successful exploitation of these vulnerabilities may result in unauthorized access, data breaches, privilege escalation, website defacement, service disruption, or complete system compromise (OWASP Foundation, 2021). Consequently, organizations increasingly recognize that identifying and mitigating vulnerabilities before deployment is essential to reducing cybersecurity risks.
<Heading 3>1.1.3 Vulnerability Assessment
To address these security challenges, vulnerability assessment has become a fundamental practice in secure software development and cybersecurity risk management. Vulnerability assessment involves systematically examining web applications to identify security weaknesses that could potentially be exploited by attackers. Automated vulnerability scanners have become widely adopted because they significantly reduce the time and effort required to discover common security flaws compared to manual penetration testing (Scambray et al., 2006). These tools assist developers and security professionals in detecting vulnerabilities during the software development lifecycle, enabling security issues to be remediated before they become exploitable.
<Heading 3>1.1.4 Web Vulnerability Standards (OWASP Top 10)
The Open Worldwide Application Security Project (OWASP) provides one of the most widely recognized standards for web application security through the OWASP Top 10, which identifies the most critical web application security risks based on industry research and real-world attack trends. Vulnerabilities such as SQL Injection, Cross-Site Scripting (XSS), Broken Access Control, Security Misconfiguration, and Identification and Authentication Failures continue to affect thousands of web applications worldwide. As a result, security assessment tools that evaluate applications against OWASP recommendations have become valuable resources for improving software security and promoting secure coding practices (OWASP Foundation, 2021).
<Heading 3>1.1.5 Existing Problems
Although numerous commercial and open-source vulnerability assessment tools are available, many existing solutions present several challenges for students, small organizations, and beginner security practitioners. Some commercial tools require expensive licensing fees, while certain open-source tools primarily focus on vulnerability detection without providing comprehensive risk assessment, centralized scan management, remediation guidance, or integrated learning resources. In addition, some tools generate highly technical reports that are difficult for inexperienced users to interpret, limiting their effectiveness as educational and decision-support platforms (PortSwigger, 2025; OWASP Foundation, 2025).
<Heading 3>1.1.6 Our System
Therefore, this project proposes VulnScan, an Intelligent Web Application Vulnerability Assessment Platform with Risk Assessment and Remediation Knowledge Base. The proposed system is designed to automatically assess web applications for multiple security vulnerabilities, calculate risk levels based on standardized assessment methods, maintain detailed audit logs, and provide remediation recommendations through an integrated knowledge base. By combining automated vulnerability assessment with educational resources and centralized management features, VulnScan aims to improve both vulnerability detection and users' understanding of web application security while providing a scalable platform capable of supporting future vulnerability assessment modules.
<Heading 2>1.2 Problem Statement
<Heading 3>1.2.1 Complexity of Existing Tools
Web application vulnerability assessment plays a crucial role in identifying security weaknesses before they can be exploited by malicious attackers. Although numerous vulnerability assessment tools are available, many existing solutions are primarily designed for experienced cybersecurity professionals and penetration testers. Tools such as OWASP ZAP and Burp Suite provide comprehensive scanning capabilities but often require extensive security knowledge to configure scan settings, interpret scan results, and understand technical vulnerability reports (OWASP Foundation, 2025; PortSwigger, 2025). This steep learning curve makes these tools less suitable for beginner developers, students, and small organizations that lack dedicated cybersecurity expertise. Consequently, there is a need for a vulnerability assessment platform that offers an intuitive interface while maintaining effective vulnerability detection capabilities.
<Heading 3>1.2.2 Lack of Integrated Risk Assessment and Remediation Guidance
Another limitation of many existing vulnerability assessment tools is their primary focus on vulnerability detection rather than vulnerability understanding and remediation. Most scanners generate technical reports that list detected vulnerabilities but provide limited explanation regarding the severity, business impact, secure coding practices, or recommended mitigation strategies. As a result, users may successfully identify vulnerabilities without fully understanding their associated risks or the appropriate remediation methods (NIST, 2020; OWASP Foundation, 2021). This limitation reduces the educational value of vulnerability assessment tools, particularly for software developers and students who require additional guidance to improve secure software development practices.
<Heading 3>1.2.3 Limited Flexibility and Centralized Management
Furthermore, many vulnerability assessment tools offer limited flexibility in managing scanning configurations and supported vulnerability modules. As cybersecurity threats continue to evolve, new vulnerability detection capabilities must be introduced without significantly modifying the overall system architecture. Traditional implementations often tightly couple scan configurations with specific vulnerability detection functions, making future system enhancement more difficult. In addition, many lightweight vulnerability scanners lack centralized management features such as user administration, security audit logging, configurable scan profiles, and modular vulnerability management. These limitations reduce system maintainability, scalability, and suitability for long-term use.
<Heading 3>1.2.4 Proposed Solution
To address the identified problems, this project proposes the development of VulnScan, an Intelligent Web Application Vulnerability Assessment Platform with Risk Assessment and Remediation Knowledge Base. The proposed system integrates automated vulnerability assessment, configurable scan profiles, risk assessment, centralized user and audit management, and a knowledge base that provides remediation recommendations and secure coding practices. The system adopts a modular architecture that supports future expansion of vulnerability detection capabilities while maintaining a user-friendly interface suitable for both beginner developers and cybersecurity practitioners.
<Heading 2>1.3 Objectives of the Project
The main objective of this project is to develop VulnScan, an intelligent web application vulnerability assessment platform that assists developers in identifying web application security vulnerabilities, assessing security risks, and providing appropriate remediation guidance through an integrated knowledge base.
To achieve the main objective, the following specific objectives are proposed:
To develop a web-based vulnerability assessment platform capable of automatically scanning web applications for common security vulnerabilities based on selected OWASP web security practices.
To implement a risk assessment mechanism that evaluates detected vulnerabilities according to their severity levels and presents the results in an understandable and structured manner.
To develop an integrated vulnerability knowledge base that provides detailed vulnerability descriptions, security impacts, remediation recommendations, secure coding practices, and reference materials to assist users in understanding and resolving identified security issues.
To implement a centralized management system that supports user authentication, role-based access control, configurable scan profiles, vulnerability management, and comprehensive security audit logging.

<Heading 3>1.4.1 Functional Scope
The proposed system includes the following functionalities:
User Authentication and Role-Based Access Control
The system supports secure user authentication using a registered email address and password. Registered users may also sign in using their Google account through single sign-on (SSO).
Two user roles are provided: Administrator and Developer.
Administrators create and manage user accounts, vulnerabilities, scan profiles, and system configurations, while Developers perform vulnerability assessments and view scan results.
Web Application Vulnerability Assessment
The system allows users to initiate vulnerability scans by specifying a target web application URL.
The scanner automatically crawls accessible web pages and performs vulnerability assessments based on the selected scan profile.
Configurable Scan Profiles
Administrators can configure predefined scan profiles consisting of selected vulnerability modules and scanning depth.
Developers select an appropriate scan profile before starting a vulnerability assessment.
Risk Assessment
The system evaluates detected vulnerabilities according to predefined severity levels and presents the results through an organized dashboard.
Risk assessment information assists users in prioritizing remediation efforts.
Vulnerability Knowledge Base
The system provides comprehensive information for each supported vulnerability, including descriptions, security impacts, remediation recommendations, secure coding practices, and OWASP references (OWASP Foundation, 2021).
Security Audit Logging
The system records significant security-related activities such as user authentication, scan execution, administrative actions, and report generation to improve accountability and traceability.
Report Generation and Data Export
The system generates structured scan reports that summarise detected vulnerabilities, their severity and risk levels, and recommended remediation actions. Authorised users can export scan results in portable formats for documentation and reporting purposes.

The proposed system is developed within the constraints of an undergraduate Final Year Project. Therefore, several limitations are identified:
The system focuses on selected common web application vulnerabilities suitable for the project scope and does not aim to provide comprehensive penetration testing comparable to commercial security assessment platforms.
The system performs automated vulnerability assessment only and does not exploit or actively attack target systems beyond the implemented detection mechanisms.
Vulnerability detection modules are implemented by the system developer. Although administrators can manage vulnerability information and scan profiles, they cannot create new detection algorithms through the system interface.
Risk assessment is intended to assist decision-making and should not replace professional cybersecurity assessment or manual penetration testing performed by experienced security professionals.

<Heading 2>2.1 Related Theories and Concepts
<Heading 3>2.1.1 Web Application Security
Web application security refers to the practice of protecting web applications from unauthorized access, malicious attacks, data breaches, and other security threats throughout the software development lifecycle. Modern web applications frequently process sensitive information such as user credentials, financial records, healthcare information, and confidential business data, making them attractive targets for cybercriminals. Consequently, security must be incorporated into every phase of application development rather than being treated as a separate activity after deployment (OWASP Foundation, 2021).
Web application vulnerabilities commonly arise from insecure coding practices, improper authentication mechanisms, insufficient input validation, security misconfigurations, outdated software components, and inadequate access control. Attackers exploit these weaknesses to gain unauthorized access, execute malicious code, steal confidential information, or disrupt normal system operations. The increasing sophistication of cyberattacks has made web application security one of the most important domains within cybersecurity research and software engineering (OWASP Foundation, 2021).
To improve application security, organizations increasingly adopt secure software development practices, regular vulnerability assessments, security testing, and continuous monitoring throughout the software development lifecycle. International standards and security frameworks such as the OWASP Top 10 and the National Institute of Standards and Technology (NIST) Cybersecurity Framework provide widely accepted guidelines for identifying and mitigating common web application security risks (OWASP Foundation, 2021).
<Heading 3>2.1.2 Vulnerability Assessment
Vulnerability assessment is a systematic process of identifying, analysing, and evaluating security weaknesses within an information system or web application before they can be exploited by attackers. Unlike penetration testing, which actively attempts to exploit identified vulnerabilities, vulnerability assessment primarily focuses on discovering and documenting security weaknesses to support risk mitigation and secure software development (Scambray et al., 2006). The objective of vulnerability assessment is to provide developers and security practitioners with sufficient information to prioritize remediation activities and strengthen the overall security posture of an application.
Modern vulnerability assessment commonly combines automated scanning techniques with manual verification to improve detection accuracy. Automated vulnerability scanners significantly reduce the time required to identify common security weaknesses such as SQL Injection, Cross-Site Scripting (XSS), insecure HTTP headers, broken authentication, and security misconfigurations. However, automated tools may also generate false positives and false negatives, making human verification an important component of comprehensive security assessment (OWASP Foundation, 2021).
Vulnerability assessment has become an essential activity within the Secure Software Development Lifecycle (SSDLC). Performing security assessments during software development enables vulnerabilities to be identified earlier, reducing remediation costs and minimizing the likelihood of security incidents after deployment. Consequently, organizations increasingly integrate automated vulnerability scanning into continuous integration and continuous deployment (CI/CD) pipelines as part of DevSecOps practices (NIST, 2020).
<Heading 3>2.1.3 OWASP Top 10
The Open Worldwide Application Security Project (OWASP) is an international non-profit organization dedicated to improving software security through open-source projects, educational resources, and industry best practices (OWASP Foundation, 2021). Among its most influential publications is the OWASP Top 10, which identifies the ten most critical web application security risks based on global industry data collected from security organizations and application assessments.
The OWASP Top 10 serves as an internationally recognized benchmark for secure web application development and is widely adopted by software developers, cybersecurity professionals, researchers, and educational institutions. Rather than introducing new vulnerabilities, the OWASP Top 10 prioritizes the most prevalent and impactful security risks affecting modern web applications, allowing organizations to focus their security efforts on the areas with the greatest potential impact (OWASP Foundation, 2021).
Since VulnScan is designed as a web application vulnerability assessment platform, the OWASP Top 10 provides the primary security framework for selecting and implementing vulnerability detection modules. In the initial version of the proposed system, VulnScan focuses on detecting selected high-priority vulnerabilities, including SQL Injection, Cross-Site Scripting (XSS), and missing HTTP Security Headers. These vulnerabilities were selected because they represent common security weaknesses that are suitable for automated detection while remaining achievable within the scope of an undergraduate Final Year Project.

<Heading 3>2.1.4 Risk Assessment
Risk assessment is an essential component of vulnerability management because it enables organizations and developers to determine the severity and priority of identified security vulnerabilities. Simply detecting vulnerabilities is insufficient, as different vulnerabilities pose different levels of risk depending on their potential impact and likelihood of exploitation. Therefore, risk assessment provides a systematic approach for evaluating vulnerabilities and assisting decision-makers in prioritizing remediation efforts (FIRST, 2023).
One of the most widely adopted standards for vulnerability risk assessment is the Common Vulnerability Scoring System (CVSS), developed by the Forum of Incident Response and Security Teams (FIRST). CVSS provides a standardized numerical score ranging from 0.0 to 10.0, allowing vulnerabilities to be consistently evaluated and compared across different systems and organizations (FIRST, 2023). The scoring methodology considers several characteristics of a vulnerability, including attack complexity, required privileges, user interaction, confidentiality impact, integrity impact, and availability impact.
CVSS classifies vulnerabilities into several severity levels, enabling organizations to prioritize remediation activities effectively. Vulnerabilities with higher scores require immediate attention because they present greater security risks, whereas lower-severity vulnerabilities may be addressed during routine maintenance. The standardized scoring system has become widely adopted by cybersecurity vendors, vulnerability scanners, and security researchers because it provides a common language for communicating security risks (Mell et al., 2007).
In the proposed VulnScan system, risk assessment is incorporated to help users understand the seriousness of detected vulnerabilities instead of merely presenting a list of findings. After vulnerabilities are identified, the system assigns a severity level and corresponding risk score, allowing users to prioritize remediation efforts more effectively. Presenting vulnerabilities according to their severity improves decision-making and enables developers to focus on addressing the most critical security issues first.

<Heading 3>2.1.5 Secure Coding Practices
Secure coding practices refer to software development techniques that minimize the introduction of security vulnerabilities during the implementation phase of the Software Development Life Cycle (SDLC). Rather than relying solely on vulnerability assessment after development, secure coding aims to prevent vulnerabilities from being introduced in the first place. This proactive approach has become a fundamental principle in modern software engineering because correcting security vulnerabilities during development is significantly less expensive than fixing them after deployment (Pressman & Maxim, 2020).
Many common web application vulnerabilities originate from poor programming practices such as insufficient input validation, improper authentication mechanisms, insecure session management, and inadequate access control. For example, SQL Injection attacks frequently occur when user input is directly incorporated into SQL queries without proper parameterization, while Cross-Site Scripting (XSS) vulnerabilities arise when untrusted user input is displayed without appropriate output encoding (OWASP Foundation, 2021).
To reduce these security risks, software developers are encouraged to adopt secure coding techniques including input validation, output encoding, parameterized SQL queries, secure password hashing, least privilege access control, proper error handling, and secure session management. These practices significantly reduce the attack surface of web applications while improving software reliability and maintainability (OWASP Foundation, 2021).
The proposed VulnScan system supports secure software development by not only identifying vulnerabilities but also providing remediation recommendations and secure coding practices through its integrated Knowledge Base. This enables developers to understand the root causes of detected vulnerabilities and apply appropriate mitigation techniques, thereby transforming vulnerability assessment into a valuable learning process.
<Heading 3>2.1.6 Role-Based Access Control (RBAC)
Role-Based Access Control (RBAC) is an access control model that restricts system access based on the roles assigned to authenticated users. Instead of assigning permissions directly to individual users, permissions are associated with predefined roles, and users inherit permissions according to their assigned roles. This approach simplifies access management, improves security, and supports the principle of least privilege by ensuring users only possess the permissions necessary to perform their assigned responsibilities (Ferraiolo et al., 2001).
RBAC has become one of the most widely implemented access control mechanisms in modern information systems because it improves scalability and administrative efficiency. Organizations with large numbers of users can manage permissions more effectively by modifying role definitions rather than configuring permissions individually for each user. Furthermore, RBAC reduces the likelihood of unauthorized access resulting from excessive user privileges or administrative errors (NIST, 2025).
The proposed VulnScan system adopts the RBAC model by defining two user roles: Administrator and Developer. Administrators are responsible for managing user accounts, scan profiles, vulnerability information, and system configurations, while Developers primarily perform vulnerability assessments, review scan results, and access the integrated Knowledge Base. Separating responsibilities according to user roles enhances system security while providing a structured management framework suitable for both educational and organizational environments.
<Heading 2>2.2 Study of Similar Existing Systems
<Heading 3>2.2.1 Review of Similar Existing System
OWASP ZAP (Zed Attack Proxy)
OWASP Zed Attack Proxy (OWASP ZAP) is one of the most widely used open-source web application security testing tools developed by the Open Worldwide Application Security Project (OWASP). The tool is specifically designed to assist developers, security testers, and penetration testers in identifying security vulnerabilities within web applications during both development and testing phases (OWASP Foundation, 2025).
OWASP ZAP provides numerous security testing features, including automated vulnerability scanning, web crawling (spidering), passive and active vulnerability scanning, fuzzing, authentication testing, session management analysis, and API security testing. In addition, the tool supports scripting and plugin extensions, allowing experienced users to customize scanning behaviour according to different testing requirements (OWASP Foundation, 2025).
One of the major strengths of OWASP ZAP is that it is completely open source and freely available, making it highly accessible for educational institutions, students, and organizations with limited financial resources. Furthermore, its active community continuously maintains and updates vulnerability detection capabilities to address newly emerging security threats.
Despite its comprehensive functionality, OWASP ZAP presents several limitations, particularly for beginner users. The large number of configuration options, scanning parameters, and technical terminology may create a steep learning curve for individuals with limited cybersecurity experience. In addition, vulnerability reports generated by OWASP ZAP primarily focus on technical findings and provide limited educational guidance regarding secure coding practices or detailed remediation explanations. Consequently, users may successfully identify vulnerabilities without fully understanding how to resolve them effectively.
The proposed VulnScan system adopts several concepts inspired by OWASP ZAP, including automated vulnerability assessment, configurable scan profiles, and vulnerability detection. However, VulnScan additionally integrates risk assessment, a remediation knowledge base, role-based administration, and centralized security audit logging to improve usability and educational value, particularly for students and beginner developers.
Burp Suite Community Edition
Burp Suite Community Edition is a widely recognized web application security testing platform developed by PortSwigger. It is extensively used by cybersecurity professionals, penetration testers, and security researchers for discovering and analysing web application vulnerabilities. Burp Suite functions primarily as an intercepting proxy that enables users to inspect, modify, and replay HTTP requests and responses exchanged between web browsers and web servers (PortSwigger, 2025).
The Community Edition includes several important security testing tools, including the Proxy, Repeater, Intruder (limited functionality), Decoder, Comparer, and basic crawling capabilities. These tools enable users to manually investigate application behaviour, manipulate requests, and identify potential security weaknesses. Compared to the Professional Edition, however, the Community Edition does not provide a fully automated vulnerability scanner, requiring users to perform many testing activities manually (PortSwigger, 2025).
A significant advantage of Burp Suite is its powerful manual testing capabilities, making it one of the most trusted tools among professional penetration testers. Its intercepting proxy provides deep visibility into web application communication, enabling advanced security analysis beyond automated vulnerability scanning.
However, Burp Suite Community Edition is generally more suitable for experienced users who possess strong knowledge of HTTP protocols, web technologies, and penetration testing methodologies. The tool also places considerable emphasis on manual testing rather than beginner-friendly automation and educational support. Consequently, students and novice developers may experience difficulties understanding scan results and identifying appropriate remediation strategies.
Unlike Burp Suite Community Edition, VulnScan focuses primarily on providing automated vulnerability assessment combined with integrated risk evaluation, educational vulnerability explanations, remediation guidance, and user-friendly dashboards. The objective is not to replace professional penetration testing tools but rather to provide an accessible platform that improves both vulnerability detection and cybersecurity learning.
Acunetix
Acunetix is a commercial web application vulnerability scanner designed to automate security testing for enterprise environments. The platform provides comprehensive vulnerability assessment capabilities, including website crawling, vulnerability scanning, authentication testing, API security assessment, and detailed security reporting. Acunetix supports the detection of thousands of known security vulnerabilities while integrating with software development workflows to facilitate continuous security testing (Invicti Security, 2025).
One of Acunetix's primary strengths is its high degree of automation. The platform automatically crawls websites, identifies potential attack surfaces, and performs extensive vulnerability analysis with minimal user intervention. In addition, Acunetix generates professional reports containing vulnerability descriptions, severity classifications, remediation recommendations, and compliance-related information, making it suitable for enterprise security management.
Despite these advantages, Acunetix is a commercial product requiring paid licensing, which may limit accessibility for students, educational institutions, and small organizations. Furthermore, while the platform provides detailed technical reports, its primary objective is professional vulnerability management rather than cybersecurity education. Consequently, users may still require additional learning resources to fully understand secure coding principles and vulnerability remediation techniques.
The proposed VulnScan system adopts several concepts from commercial vulnerability scanners, including automated assessment, structured reporting, and risk prioritization. However, VulnScan differentiates itself by integrating an educational knowledge base, configurable vulnerability modules, centralized user management, and security audit logging while maintaining accessibility for educational and research purposes.

<Heading 2>2.3 Research Gap
The literature review indicates that numerous vulnerability assessment tools have been developed to identify security weaknesses within web applications. Open-source tools such as OWASP ZAP provide comprehensive automated vulnerability scanning, while Burp Suite Community Edition offers powerful manual security testing capabilities. Commercial solutions such as Acunetix further extend vulnerability management through enterprise reporting and workflow integration. Although these systems perform effectively within their intended domains, several research and practical gaps remain.
Firstly, many existing vulnerability assessment tools primarily focus on identifying security vulnerabilities without providing sufficient educational support for users. Scan reports frequently contain technical terminology that may be difficult for students, beginner developers, and inexperienced security practitioners to interpret. As a result, users may identify vulnerabilities successfully but still lack sufficient understanding of their causes, impacts, and remediation techniques (OWASP Foundation, 2021).
Secondly, many existing tools separate vulnerability detection from security knowledge. Users often need to consult external documentation, OWASP Cheat Sheets, or additional learning resources to understand detected vulnerabilities and implement appropriate secure coding practices. This fragmented learning process reduces the overall effectiveness of vulnerability assessment, particularly in educational environments.
Thirdly, although several commercial vulnerability management platforms support centralized administration, these solutions are often associated with significant licensing costs that may limit accessibility for educational institutions and small organizations. Conversely, many open-source solutions provide extensive scanning functionality but lack integrated features such as configurable scan profiles, centralized vulnerability management, role-based administration, and comprehensive security audit logging.
Finally, many existing systems are designed primarily for experienced cybersecurity professionals. Their interfaces, configuration options, and technical reporting may present a significant learning curve for users with limited cybersecurity experience. Consequently, there remains a need for a user-friendly vulnerability assessment platform that combines effective vulnerability detection with educational guidance and centralized management capabilities.
To address these identified gaps, this project proposes VulnScan, an intelligent web application vulnerability assessment platform that integrates automated vulnerability assessment, configurable scan profiles, centralized user management, comprehensive audit logging, risk assessment, and an integrated vulnerability knowledge base within a single web-based application. By combining technical vulnerability assessment with educational support, the proposed system aims to improve both application security and cybersecurity learning outcomes.

<Heading 2>4.1 Architecture Design
<Heading 3>4.1.1 Layered System Architecture (Logical View)
Figure 4.1: Layered System Architecture of VulnScan (Logical View)
The overall architecture of VulnScan is designed using a layered architecture to separate system responsibilities into distinct layers, thereby improving maintainability, scalability, and modularity. As illustrated in Figure 4.1, the system consists of five primary layers: the Presentation Layer, API Layer, Business Logic Layer, Scanner Engine Layer, and Data Layer. Each layer performs a specific function while interacting with adjacent layers through well-defined interfaces, reducing coupling between system components and simplifying future maintenance (Pressman & Maxim, 2020).
The Presentation Layer provides separate interfaces for Developers and Administrators through a web application. Developers are able to initiate vulnerability scans, view and select predefined scan profiles, and review scan results, whereas Administrators perform system management tasks such as user and scan profile management, vulnerability management, and monitoring of system activities.
The Business Logic Layer contains the core application modules responsible for implementing the business rules of the system. These modules include Authentication, Scan Management, Scan Profile Management, Vulnerability Management, and Audit Logging. The Business Logic Layer validates user requests, applies access control, manages application data, and coordinates interactions with the Scanner Engine.
The Scanner Engine Layer is responsible for performing vulnerability assessments on target web applications. It consists of a Web Crawler and multiple independent vulnerability detection modules, including SQL Injection, Cross-Site Scripting (XSS), and HTTP Security Header analysis. The modular design enables additional vulnerability detection modules, such as Cross-Site Request Forgery (CSRF), XML External Entity (XXE), Server-Side Request Forgery (SSRF), and Command Injection, to be incorporated in future versions without requiring significant modifications to the overall system architecture.
The Data Layer utilises Microsoft SQL Server to manage application data, including user accounts, scan information, vulnerability definitions, scan profiles, findings, discovered pages, and security audit logs. This layered architecture promotes separation of concerns, facilitates future system enhancements, and ensures that each system component can be developed, tested, and maintained independently.
<Heading 3>4.1.2 Deployment Architecture
In addition to the logical layered view, the physical deployment of VulnScan must be considered. VulnScan is designed as a client-server web application and is targeted for deployment on the Microsoft Azure cloud platform. Users access the system through a web browser over HTTPS using the public URL of the deployed application. The Flask web application, which serves both the frontend user interface and the backend REST API together with the Scanner Engine, is hosted as an Azure App Service. The application connects to Microsoft SQL Server through the SQLAlchemy object-relational mapper; in the target deployment, the database is provisioned as Azure SQL Database, a managed cloud service based on the Microsoft SQL Server engine. When an assessment is performed, the Scanner Engine sends HTTP or HTTPS requests to the target web application being evaluated. When a user signs in through Google single sign-on, the application communicates with the Google OAuth 2.0 authorisation service over HTTPS. <Heading 2>4.2 Database Design
The database is designed to provide a structured and reliable repository for managing user information, scan configurations, vulnerability definitions, scan results, and system activities. Microsoft SQL Server was selected as the database management system because of its robustness, transactional reliability, advanced security features, and seamless integration with SQLAlchemy. These capabilities make it suitable for managing the relational data required by VulnScan while supporting future scalability and maintenance. During deployment, the database is provisioned as Azure SQL Database, a fully managed cloud service built on the Microsoft SQL Server engine that provides automated backups, high availability, and elastic scalability.
The database design follows the principles of relational database modelling and has been normalised to Third Normal Form (3NF) to minimise data redundancy and maintain data consistency. Related data are separated into individual entities, with relationships established through primary and foreign keys to preserve referential integrity. This approach improves data organisation, simplifies maintenance, and reduces the risk of update anomalies.
As illustrated in Figure 4.3, the VulnScan database consists of eight entities: User, Scan, ScanProfile, ProfileModule, Vulnerability, DiscoveredPage, Finding, and SecurityAuditLog. Each entity is responsible for storing a specific category of information required by the system. The relationships among these entities enable the system to manage vulnerability scanning activities, configurable scan profiles, modular vulnerability definitions, detected findings, discovered web pages, and security audit records while maintaining consistency across the database.
The User entity manages user accounts, authentication information, and user roles, providing the foundation for role-based access control. The Scan entity stores information relating to each vulnerability assessment session and acts as the central entity connecting scan profiles, discovered pages, and detected findings. During execution, the Web Crawler records discovered web pages in the DiscoveredPage entity, while identified vulnerabilities are stored within the Finding entity and linked to the corresponding vulnerability definitions maintained in the Vulnerability entity.
To improve flexibility and future scalability, VulnScan adopts a configurable scan profile mechanism through the ScanProfile and ProfileModule entities. Rather than hardcoding supported vulnerabilities within the application, administrators can configure which vulnerability detection modules belong to each scan profile. This modular approach allows future detection modules, such as Cross-Site Request Forgery (CSRF), XML External Entity (XXE), Server-Side Request Forgery (SSRF), and Command Injection, to be incorporated without redesigning the database structure.
Finally, the SecurityAuditLog entity records significant user and system activities throughout the application. Maintaining audit records enhances accountability, supports security monitoring, and facilitates future forensic analysis by preserving a history of important events performed within the system.

<Heading 3>4.4.2 User Authentication Process
The user authentication process ensures that only authorised users can access the VulnScan platform. When a user signs in using their registered email address and password, the request is forwarded to the Flask REST API, where the credentials are validated against the information stored in the User entity. Passwords are stored and verified using secure hashing techniques to protect user credentials during authentication.
Upon successful authentication, the system generates a JSON Web Token (JWT) that is returned to the client. The JWT is included in subsequent requests to verify the user's identity and assigned role. Based on the authenticated role, the system redirects the user to either the Developer Dashboard or the Administrator Dashboard, ensuring that users only access functions relevant to their responsibilities. Failed authentication attempts are recorded in the SecurityAuditLog to support system monitoring and security auditing.
In addition to local authentication, VulnScan supports single sign-on through Google using the OAuth 2.0 authorisation code flow. When a user chooses to sign in with Google, the system redirects the user to Google's authorisation server, where the user consents to share their verified email address. The backend then exchanges the returned authorisation code for an access token and retrieves the user's profile information. The verified email address is matched against the User entity; if a matching active account exists, authentication succeeds and a JWT is issued. User accounts are provisioned by Administrators, so accounts are not created automatically during Google authentication. Successful and failed sign-in attempts, including Google authentication, are recorded in the SecurityAuditLog.

This sequence diagram illustrates the user authentication process of VulnScan. It shows how a user submits their email address and password, how the request is validated by the Flask API and the authentication service, and how the service verifies the stored password hash and account status against the database before issuing a JSON Web Token (JWT). <Heading 3>4.4.3 Vulnerability Scanning Process
The vulnerability scanning process begins when a developer creates a new scan by providing a target website URL and selecting an appropriate scan profile. The selected scan profile determines which vulnerability detection modules will be executed during the assessment.
The Scanner Engine first activates the Web Crawler to discover accessible pages within the target website. The discovered pages are recorded in the DiscoveredPage entity before being analysed by the enabled vulnerability detection modules. During the current implementation, the Scanner Engine supports SQL Injection (SQLi), Cross-Site Scripting (XSS), and HTTP Security Header analysis. Any identified vulnerabilities are stored as findings together with their severity, affected location, supporting evidence, and remediation recommendations.
After the scanning process is completed, the scan status is updated and the results are presented to the user through the Scan Result interface. The modular design of the Scanner Engine allows additional vulnerability detection modules to be incorporated in future versions without modifying the overall system architecture.

<Heading 3>4.4.4 Vulnerability Detection Modules
VulnScan supports three vulnerability detection modules in its initial version: SQL Injection (SQLi), Cross-Site Scripting (XSS), and HTTP Security Header analysis. These modules are executed against the pages discovered by the Web Crawler according to the modules enabled in the selected scan profile, and they are represented by the Vulnerability and ProfileModule entities in the database design. The SQL Injection detection module tests the input parameters of each page by sending crafted payloads and analysing the responses for SQL errors or anomalous behaviour; when a vulnerability is indicated, a Finding is recorded together with its severity, risk score, and supporting evidence. Figure 4.11 presents the flowchart of the SQL Injection detection algorithm. The XSS module applies a similar payload and response analysis to detect whether untrusted input is reflected and executed in the returned page, while the HTTP Security Header module inspects the response headers of each page against recommended security header settings. The detection modules are implemented as independent components, allowing additional modules to be added in the future without modifying the core scanner architecture.

<Heading 3>4.4.5 Security Audit Logging Process
To improve system accountability and security monitoring, VulnScan records important user and system activities using the SecurityAuditLog entity. Whenever significant events occur, such as user authentication, scan creation, vulnerability management, or administrative operations, the Business Logic Layer automatically generates audit records containing the event description, event time, responsible user, and related system information.
The audit logging mechanism enables administrators to monitor system activities, investigate security incidents, and maintain a historical record of important operations. Centralising these records also supports future maintenance and forensic analysis by providing a complete history of significant events performed within the application.
Figure 4.12: Security Audit Logging Activity Diagram
Purpose:
This activity diagram illustrates how VulnScan records security audit logs using two swimlanes. When a significant action occurs, such as authentication, scan creation, or an administrative operation, the Business Logic layer captures the event context, decides whether the event is significant, and composes an audit record containing the category, action, description, responsible user, and event time. Significant records are inserted into the SecurityAuditLog entity in the database, where administrators can subsequently review them to support monitoring and forensic analysis. <Heading 3>4.4.6 Application Programming Interface (API) Design
VulnScan exposes its core services through a representational state transfer (REST) application programming interface (API). The Presentation Layer consumes this API, which is processed by the API Layer and returns responses in JavaScript Object Notation (JSON) format. Access to the API is protected using the JSON Web Tokens (JWT) described in Section 4.4.1, which clients include as bearer tokens in the Authorization header of each request. Permissions for each endpoint are enforced according to the role of the authenticated user, consistent with the role-based access control model presented in this chapter. <Heading 3>4.4.7 Design Rationale and Trade-offs
The design decisions for VulnScan balance technical feasibility, maintainability, and security. A layered architecture separates presentation, business logic, and data concerns, which simplifies development, testing, and maintenance; the main trade-off is the additional communication between layers, which is acceptable for the scale of this system. The relational database is normalised to Third Normal Form (3NF) to reduce redundancy and prevent update anomalies, at the cost of requiring joins when retrieving data; given the modest data volumes produced by vulnerability scans, this overhead is negligible. JWT-based stateless authentication was preferred over server-side session storage because it avoids maintaining session state between requests and is well suited to the client-server REST architecture. Flask was selected for its lightweight and modular structure, while Microsoft SQL Server was chosen for its robustness, transactional reliability, and integration with the SQLAlchemy object-relational mapper. Finally, the scanner engine is designed as an independent module with pluggable detection modules so that future vulnerability checks can be added without redesigning the core system.
