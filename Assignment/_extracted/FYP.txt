Abstract 
Modern web applications have become essential platforms for delivering online services across 
various industries. However, their increasing complexity has also introduced numerous security 
vulnerabilities that may lead to unauthorized access, data breaches, and service disruption. 
Although many vulnerability assessment tools are available, existing solutions are often designed 
for experienced cybersecurity professionals and primarily focus on vulnerability detection while 
providing limited educational guidance and remediation support. This project proposes VulnScan, 
an Intelligent Web Application Vulnerability Assessment Platform with Risk Assessment and 
Remediation Knowledge Base, to provide an accessible and educational solution for identifying 
and understanding common web application security vulnerabilities. The proposed system 
enables developers to perform automated vulnerability assessments by scanning target web 
applications for selected vulnerabilities, including SQL Injection (SQL Injection), Cross-Site 
Scripting (XSS), and HTTP Security Header misconfigurations. In addition to vulnerability 
detection, the system incorporates configurable scan profiles, risk assessment, role-based access 
control, security audit logging, and an integrated knowledge base containing vulnerability 
descriptions, security impacts, secure coding practices, and remediation recommendations. The 
system adopts the Agile Software Development methodology, allowing iterative planning, design, 
implementation, testing, and continuous improvement throughout the project lifecycle. The 
system architecture follows a layered design consisting of the Presentation Layer, REST API 
Layer, Business Logic Layer, Scanner Engine, and Data Layer to improve modularity, scalability, 
and maintainability. Database normalization and modular vulnerability management further 
support future system expansion. Functional and non-functional testing are conducted to verify 
that the implemented system satisfies the specified requirements and performs reliably under 
normal operating conditions. Overall, VulnScan demonstrates that integrating automated 
vulnerability assessment with educational resources, centralized management, and risk evaluation 
can improve both web application security and users' understanding of secure software 
development. The proposed platform provides a practical and scalable foundation for future 
enhancement through additional vulnerability detection modules and advanced security analysis 
capabilities.

Introduction 
 

 
1.0 Introduction 
This chapter introduces the proposed project, VulnScan: An Intelligent Web Application 
Vulnerability Assessment Platform with Risk Assessment and Remediation Knowledge Base. It 
presents the background and context of web application security, discusses the problems that 
motivate the development of the proposed system, and outlines the project's objectives, scope, 
limitations, and significance. In addition, this chapter provides an overview of the report structure to 
guide readers through the subsequent chapters. The purpose of this chapter is to establish a clear 
understanding of the project's motivation, research direction, and expected contributions in 
addressing current web application security challenges. 
1.1 Background and Context 
1.1.1 Cybersecurity 
The rapid growth of digital technologies has transformed the way organizations, businesses, 
educational institutions, and government agencies deliver services through web applications. 
Online platforms are now widely used for banking, healthcare, education, e-commerce, and 
cloud-based services, enabling users to access information and perform transactions conveniently 
from anywhere with an Internet connection. As web applications continue to store and process 
sensitive information such as personal records, financial data, authentication credentials, and 
confidential business information, ensuring the security of these applications has become one of 
the most critical concerns in modern cybersecurity (OWASP Foundation, 2021; NIST, 2020).  
1.1.2 Web Applications 
Despite significant advancements in software development practices, web applications remain 
one of the most frequently targeted attack surfaces by cybercriminals. Security vulnerabilities 
introduced during software development, insecure configurations, outdated software components, 
and improper input validation expose web applications to numerous cyberattacks. Successful 
exploitation of these vulnerabilities may result in unauthorized access, data breaches, privilege 
escalation, website defacement, service disruption, or complete system compromise (OWASP 
Foundation, 2021). Consequently, organizations increasingly recognize that identifying and 
mitigating vulnerabilities before deployment is essential to reducing cybersecurity risks.​ 

 
1.1.3 Web Vulnerabilities 
To address these security challenges, vulnerability assessment has become a fundamental practice 
in secure software development and cybersecurity risk management. Vulnerability assessment 
involves systematically examining web applications to identify security weaknesses that could 
potentially be exploited by attackers. Automated vulnerability scanners have become widely 
adopted because they significantly reduce the time and effort required to discover common 
security flaws compared to manual penetration testing (Scambray et al., 2021). . These tools assist 
developers and security professionals in detecting vulnerabilities during the software 
development lifecycle, enabling security issues to be remediated before they become exploitable. 
1.1.4 Vulnerability Assessment 
The Open Worldwide Application Security Project (OWASP) provides one of the most widely 
recognized standards for web application security through the OWASP Top 10, which identifies 
the most critical web application security risks based on industry research and real-world attack 
trends. Vulnerabilities such as SQL Injection, Cross-Site Scripting (XSS), Broken Access 
Control, Security Misconfiguration, and Identification and Authentication Failures continue to 
affect thousands of web applications worldwide. As a result, security assessment tools that 
evaluate applications against OWASP recommendations have become valuable resources for 
improving software security and promoting secure coding practices (OWASP Foundation, 2021). 
1.1.5 Existing Problems 
Although numerous commercial and open-source vulnerability assessment tools are available, 
many existing solutions present several challenges for students, small organizations, and beginner 
security practitioners. Some commercial tools require expensive licensing fees, while certain 
open-source tools primarily focus on vulnerability detection without providing comprehensive 
risk assessment, centralized scan management, remediation guidance, or integrated learning 
resources. In addition, some tools generate highly technical reports that are difficult for 
inexperienced users to interpret, limiting their effectiveness as educational and decision-support 
platforms (PortSwigger, 2025; OWASP Foundation, 2025). 

 
1.1.6 Our System  
Therefore, this project proposes VulnScan, an Intelligent Web Application Vulnerability 
Assessment Platform with Risk Assessment and Remediation Knowledge Base. The proposed 
system is designed to automatically assess web applications for multiple security vulnerabilities, 
calculate risk levels based on standardized assessment methods, maintain detailed audit logs, and 
provide remediation recommendations through an integrated knowledge base. By combining 
automated vulnerability assessment with educational resources and centralized management 
features, VulnScan aims to improve both vulnerability detection and users' understanding of web 
application security while providing a scalable platform capable of supporting future vulnerability 
assessment modules. 
1.2 Problem Statement 
1.2.1 Complexity of Existing Tools  
Web application vulnerability assessment plays a crucial role in identifying security weaknesses 
before they can be exploited by malicious attackers. Although numerous vulnerability assessment 
tools are available, many existing solutions are primarily designed for experienced cybersecurity 
professionals and penetration testers. Tools such as OWASP ZAP and Burp Suite provide 
comprehensive scanning capabilities but often require extensive security knowledge to configure 
scan settings, interpret scan results, and understand technical vulnerability reports (OWASP 
Foundation, 2025; PortSwigger, 2025). This steep learning curve makes these tools less suitable 
for beginner developers, students, and small organizations that lack dedicated cybersecurity 
expertise. Consequently, there is a need for a vulnerability assessment platform that offers an 
intuitive interface while maintaining effective vulnerability detection capabilities. 
 
 
 
 
 

 
1.2.2 Lack of Integrated Risk Assessment and Remediation Guidance  
Another limitation of many existing vulnerability assessment tools is their primary focus on 
vulnerability detection rather than vulnerability understanding and remediation. Most scanners 
generate technical reports that list detected vulnerabilities but provide limited explanation 
regarding the severity, business impact, secure coding practices, or recommended mitigation 
strategies. As a result, users may successfully identify vulnerabilities without fully understanding 
their associated risks or the appropriate remediation methods (NIST, 2020; OWASP Foundation, 
2021). This limitation reduces the educational value of vulnerability assessment tools, particularly 
for software developers and students who require additional guidance to improve secure software 
development practices. 
1.2.3 Limited Flexibility and Centralized Management 
Furthermore, many vulnerability assessment tools offer limited flexibility in managing scanning 
configurations and supported vulnerability modules. As cybersecurity threats continue to evolve, 
new vulnerability detection capabilities must be introduced without significantly modifying the 
overall system architecture. Traditional implementations often tightly couple scan configurations 
with specific vulnerability detection functions, making future system enhancement more difficult. 
In addition, many lightweight vulnerability scanners lack centralized management features such 
as user administration, security audit logging, configurable scan profiles, and modular 
vulnerability management. These limitations reduce system maintainability, scalability, and 
suitability for long-term use. 
1.2.4 Proposed Solution 
To address the identified problems, this project proposes the development of VulnScan, an 
Intelligent Web Application Vulnerability Assessment Platform with Risk Assessment and 
Remediation Knowledge Base. The proposed system integrates automated vulnerability 
assessment, configurable scan profiles, risk assessment, centralized user and audit management, 
and a knowledge base that provides remediation recommendations and secure coding practices. 
The system adopts a modular architecture that supports future expansion of vulnerability 
detection capabilities while maintaining a user-friendly interface suitable for both beginner 
developers and cybersecurity practitioners. 

 
1.3 Objectives of the Project 
The main objective of this project is to develop VulnScan, an intelligent web application 
vulnerability assessment platform that assists developers in identifying web application security 
vulnerabilities, assessing security risks, and providing appropriate remediation guidance through 
an integrated knowledge base. 
To achieve the main objective, the following specific objectives are proposed: 
1.​ To design a web-based vulnerability assessment platform capable of automatically 
scanning web applications for common security vulnerabilities based on selected OWASP 
web security practices. 
2.​ To implement a risk assessment mechanism that evaluates detected vulnerabilities 
according to their severity levels and presents the results in an understandable and 
structured manner. 
3.​ To develop an integrated vulnerability knowledge base that provides detailed 
vulnerability descriptions, security impacts, remediation recommendations, secure coding 
practices, and reference materials to assist users in understanding and resolving identified 
security issues. 
4.​ To design a centralized management system that supports user authentication, role-based 
access control, configurable scan profiles, vulnerability management, and comprehensive 
security audit logging.

The proposed system is developed within the constraints of an undergraduate Final Year Project.

1.​ The system focuses on selected common web application vulnerabilities suitable for the

security professionals.

small-scale security assessment environments.

Secondly, the project serves as a valuable educational platform for students and beginner

Thirdly, the proposed system provides practical benefits to small and medium-sized organizations

Finally, this project contributes to the academic and research community by demonstrating the

Overall, the proposed system aims to improve web application security awareness while

2.0 Literature Review 
This chapter reviews the literature related to web application security, vulnerability assessment 
methodologies, and technologies relevant to the development of the proposed system. The review 
begins by discussing fundamental concepts including web application security, vulnerability 
assessment, the OWASP Top 10, risk assessment, secure coding practices, and role-based access 
control. Subsequently, several existing vulnerability assessment tools are analysed and compared to 
identify their strengths and limitations. Finally, the research gaps identified from the literature review 
are discussed to justify the development of the proposed system, VulnScan. 
2.1 Related Theories and Concepts 
2.1.1 Web Application Security 
Web application security refers to the practice of protecting web applications from unauthorized 
access, malicious attacks, data breaches, and other security threats throughout the software 
development lifecycle. Modern web applications frequently process sensitive information such as 
user credentials, financial records, healthcare information, and confidential business data, making 
them attractive targets for cybercriminals. Consequently, security must be incorporated into every 
phase of application development rather than being treated as a separate activity after deployment 
(OWASP Foundation, 2021). 
Web application vulnerabilities commonly arise from insecure coding practices, improper 
authentication mechanisms, insufficient input validation, security misconfigurations, outdated 
software components, and inadequate access control. Attackers exploit these weaknesses to gain 
unauthorized access, execute malicious code, steal confidential information, or disrupt normal 
system operations. The increasing sophistication of cyberattacks has made web application 
security one of the most important domains within cybersecurity research and software 
engineering (OWASP Foundation, 2021). 
To improve application security, organizations increasingly adopt secure software development 
practices, regular vulnerability assessments, security testing, and continuous monitoring 
throughout the software development lifecycle. International standards and security frameworks 
such as the OWASP Top 10 and the National Institute of Standards and Technology (NIST) 

 
Cybersecurity Framework provide widely accepted guidelines for identifying and mitigating 
common web application security risks (OWASP Foundation, 2021). 
2.1.2 Vulnerability Assessment 
Vulnerability assessment is a systematic process of identifying, analysing, and evaluating security 
weaknesses within an information system or web application before they can be exploited by 
attackers. Unlike penetration testing, which actively attempts to exploit identified vulnerabilities, 
vulnerability assessment primarily focuses on discovering and documenting security weaknesses 
to support risk mitigation and secure software development (Scambray et al., 2011). The objective 
of vulnerability assessment is to provide developers and security practitioners with sufficient 
information to prioritize remediation activities and strengthen the overall security posture of an 
application. 
Modern vulnerability assessment commonly combines automated scanning techniques with 
manual verification to improve detection accuracy. Automated vulnerability scanners 
significantly reduce the time required to identify common security weaknesses such as SQL 
Injection, Cross-Site Scripting (XSS), insecure HTTP headers, broken authentication, and 
security misconfigurations. However, automated tools may also generate false positives and false 
negatives, making human verification an important component of comprehensive security 
assessment (OWASP Foundation, 2021). 
Vulnerability assessment has become an essential activity within the Secure Software 
Development Lifecycle (SSDLC). Performing security assessments during software development 
enables vulnerabilities to be identified earlier, reducing remediation costs and minimizing the 
likelihood of security incidents after deployment. Consequently, organizations increasingly 
integrate automated vulnerability scanning into continuous integration and continuous 
deployment (CI/CD) pipelines as part of DevSecOps practices (NIST, 2020). 
 
 
 
 

 
2.1.3 OWASP Top 10 
The Open Worldwide Application Security Project (OWASP) is an international non-profit 
organization dedicated to improving software security through open-source projects, educational 
resources, and industry best practices (OWASP Foundation, 2021). Among its most influential 
publications is the OWASP Top 10, which identifies the ten most critical web application security 
risks based on global industry data collected from security organizations and application 
assessments. 
The OWASP Top 10 serves as an internationally recognized benchmark for secure web 
application development and is widely adopted by software developers, cybersecurity 
professionals, researchers, and educational institutions. Rather than introducing new 
vulnerabilities, the OWASP Top 10 prioritizes the most prevalent and impactful security risks 
affecting modern web applications, allowing organizations to focus their security efforts on the 
areas with the greatest potential impact (OWASP Foundation, 2021). 
Since VulnScan is designed as a web application vulnerability assessment platform, the OWASP 
Top 10 provides the primary security framework for selecting and implementing vulnerability 
detection modules. In the initial version of the proposed system, VulnScan focuses on detecting 
selected high-priority vulnerabilities, including SQL Injection, Cross-Site Scripting (XSS), and 
missing HTTP Security Headers. These vulnerabilities were selected because they represent 
common security weaknesses that are suitable for automated detection while remaining 
achievable within the scope of an undergraduate Final Year Project.

2.1.4 Risk Assessment 
Risk assessment is an essential component of vulnerability management because it enables 
organizations and developers to determine the severity and priority of identified security 
vulnerabilities. Simply detecting vulnerabilities is insufficient, as different vulnerabilities pose 
different levels of risk depending on their potential impact and likelihood of exploitation. 
Therefore, risk assessment provides a systematic approach for evaluating vulnerabilities and 
assisting decision-makers in prioritizing remediation efforts (FIRST, 2023). 
One of the most widely adopted standards for vulnerability risk assessment is the Common 
Vulnerability Scoring System (CVSS), developed by the Forum of Incident Response and 
Security Teams (FIRST). CVSS provides a standardized numerical score ranging from 0.0 to 
10.0, allowing vulnerabilities to be consistently evaluated and compared across different systems 
and organizations (FIRST, 2023). The scoring methodology considers several characteristics of a 

 
vulnerability, including attack complexity, required privileges, user interaction, confidentiality 
impact, integrity impact, and availability impact. 
CVSS classifies vulnerabilities into several severity levels, enabling organizations to prioritize 
remediation activities effectively. Vulnerabilities with higher scores require immediate attention 
because they present greater security risks, whereas lower-severity vulnerabilities may be 
addressed during routine maintenance. The standardized scoring system has become widely 
adopted by cybersecurity vendors, vulnerability scanners, and security researchers because it 
provides a common language for communicating security risks (Mell et al., 2007). 
In the proposed VulnScan system, risk assessment is incorporated to help users understand the 
seriousness of detected vulnerabilities instead of merely presenting a list of findings. After 
vulnerabilities are identified, the system assigns a severity level and corresponding risk score, 
allowing users to prioritize remediation efforts more effectively. Presenting vulnerabilities 
according to their severity improves decision-making and enables developers to focus on 
addressing the most critical security issues first.

2.1.5 Secure Coding Practices 
Secure coding practices refer to software development techniques that minimize the introduction 
of security vulnerabilities during the implementation phase of the Software Development Life 
Cycle (SDLC). Rather than relying solely on vulnerability assessment after development, secure 
coding aims to prevent vulnerabilities from being introduced in the first place. This proactive 
approach has become a fundamental principle in modern software engineering because correcting 
security vulnerabilities during development is significantly less expensive than fixing them after 
deployment (Pressman & Maxim, 2020). 
Many common web application vulnerabilities originate from poor programming practices such 
as insufficient input validation, improper authentication mechanisms, insecure session 
management, and inadequate access control. For example, SQL Injection attacks frequently occur 
when user input is directly incorporated into SQL queries without proper parameterization, while 
Cross-Site Scripting (XSS) vulnerabilities arise when untrusted user input is displayed without 
appropriate output encoding (OWASP Foundation, 2021). 
To reduce these security risks, software developers are encouraged to adopt secure coding 
techniques including input validation, output encoding, parameterized SQL queries, secure 
password hashing, least privilege access control, proper error handling, and secure session 
management. These practices significantly reduce the attack surface of web applications while 
improving software reliability and maintainability (OWASP Foundation, 2021). 
The proposed VulnScan system supports secure software development by not only identifying 
vulnerabilities but also providing remediation recommendations and secure coding practices 
through its integrated Knowledge Base. This enables developers to understand the root causes of 
detected vulnerabilities and apply appropriate mitigation techniques, thereby transforming 
vulnerability assessment into a valuable learning process. 
 
 
 
 

 
2.1.6 Role-Based Access Control (RBAC) 
Role-Based Access Control (RBAC) is an access control model that restricts system access based 
on the roles assigned to authenticated users. Instead of assigning permissions directly to 
individual users, permissions are associated with predefined roles, and users inherit permissions 
according to their assigned roles. This approach simplifies access management, improves 
security, and supports the principle of least privilege by ensuring users only possess the 
permissions necessary to perform their assigned responsibilities (Ferraiolo et al., 2001). 
RBAC has become one of the most widely implemented access control mechanisms in modern 
information systems because it improves scalability and administrative efficiency. Organizations 
with large numbers of users can manage permissions more effectively by modifying role 
definitions rather than configuring permissions individually for each user. Furthermore, RBAC 
reduces the likelihood of unauthorized access resulting from excessive user privileges or 
administrative errors (NIST, 2025). 
The proposed VulnScan system adopts the RBAC model by defining two user roles: 
Administrator and Developer. Administrators are responsible for managing user accounts, scan 
profiles, vulnerability information, and system configurations, while Developers primarily 
perform vulnerability assessments, review scan results, and access the integrated Knowledge 
Base. Separating responsibilities according to user roles enhances system security while 
providing a structured management framework suitable for both educational and organizational 
environments. 
 
 
 
 
 
 

 
2.2 Study of Similar Existing Systems 
2.2.1 Review of Similar Existing System 
A.​ OWASP ZAP (Zed Attack Proxy) 
OWASP Zed Attack Proxy (OWASP ZAP) is one of the most widely used open-source web 
application security testing tools developed by the Open Worldwide Application Security Project 
(OWASP). The tool is specifically designed to assist developers, security testers, and penetration 
testers in identifying security vulnerabilities within web applications during both development 
and testing phases (OWASP Foundation, 2025). 
 
OWASP ZAP provides numerous security testing features, including automated vulnerability 
scanning, web crawling (spidering), passive and active vulnerability scanning, fuzzing, 
authentication testing, session management analysis, and API security testing. In addition, the 
tool supports scripting and plugin extensions, allowing experienced users to customize scanning 
behaviour according to different testing requirements (OWASP Foundation, 2025). 
 
One of the major strengths of OWASP ZAP is that it is completely open source and freely 
available, making it highly accessible for educational institutions, students, and organizations 
with limited financial resources. Furthermore, its active community continuously maintains and 
updates vulnerability detection capabilities to address newly emerging security threats. 
 
Despite its comprehensive functionality, OWASP ZAP presents several limitations, particularly 
for beginner users. The large number of configuration options, scanning parameters, and technical 
terminology may create a steep learning curve for individuals with limited cybersecurity 
experience. In addition, vulnerability reports generated by OWASP ZAP primarily focus on 
technical findings and provide limited educational guidance regarding secure coding practices or 
detailed remediation explanations. Consequently, users may successfully identify vulnerabilities 
without fully understanding how to resolve them effectively. 

 
The proposed VulnScan system adopts several concepts inspired by OWASP ZAP, including 
automated vulnerability assessment, configurable scan profiles, and vulnerability detection. 
However, VulnScan additionally integrates risk assessment, a remediation knowledge base, 
role-based administration, and centralized security audit logging to improve usability and 
educational value, particularly for students and beginner developers. 
B.​ Burp Suite Community Edition 
Burp Suite Community Edition is a widely recognized web application security testing platform 
developed by PortSwigger. It is extensively used by cybersecurity professionals, penetration 
testers, and security researchers for discovering and analysing web application vulnerabilities. 
Burp Suite functions primarily as an intercepting proxy that enables users to inspect, modify, and 
replay HTTP requests and responses exchanged between web browsers and web servers 
(PortSwigger, 2025). 
The Community Edition includes several important security testing tools, including the Proxy, 
Repeater, Intruder (limited functionality), Decoder, Comparer, and basic crawling capabilities. 
These tools enable users to manually investigate application behaviour, manipulate requests, and 
identify potential security weaknesses. Compared to the Professional Edition, however, the 
Community Edition does not provide a fully automated vulnerability scanner, requiring users to 
perform many testing activities manually (PortSwigger, 2025). 
A significant advantage of Burp Suite is its powerful manual testing capabilities, making it one of 
the most trusted tools among professional penetration testers. Its intercepting proxy provides deep 
visibility into web application communication, enabling advanced security analysis beyond 
automated vulnerability scanning. 
However, Burp Suite Community Edition is generally more suitable for experienced users who 
possess strong knowledge of HTTP protocols, web technologies, and penetration testing 
methodologies. The tool also places considerable emphasis on manual testing rather than 
beginner-friendly automation and educational support. Consequently, students and novice 
developers may experience difficulties understanding scan results and identifying appropriate 
remediation strategies. 
 

 
Unlike Burp Suite Community Edition, VulnScan focuses primarily on providing automated 
vulnerability assessment combined with integrated risk evaluation, educational vulnerability 
explanations, remediation guidance, and user-friendly dashboards. The objective is not to replace 
professional penetration testing tools but rather to provide an accessible platform that improves 
both vulnerability detection and cybersecurity learning. 
C.​ Acunetix 
Acunetix is a commercial web application vulnerability scanner designed to automate security 
testing for enterprise environments. The platform provides comprehensive vulnerability 
assessment capabilities, including website crawling, vulnerability scanning, authentication 
testing, API security assessment, and detailed security reporting. Acunetix supports the detection 
of thousands of known security vulnerabilities while integrating with software development 
workflows to facilitate continuous security testing (Invicti Security, 2025). 
One of Acunetix's primary strengths is its high degree of automation. The platform automatically 
crawls websites, identifies potential attack surfaces, and performs extensive vulnerability analysis 
with minimal user intervention. In addition, Acunetix generates professional reports containing 
vulnerability

Despite these advantages, Acunetix is a commercial product requiring paid licensing, which may 
limit accessibility for students, educational institutions, and small organizations. Furthermore, 
while the platform provides detailed technical reports, its primary objective is professional 
vulnerability management rather than cybersecurity education. Consequently, users may still 
require additional learning resources to fully understand secure coding principles and 
vulnerability remediation techniques. 
The proposed VulnScan system adopts several concepts from commercial vulnerability scanners, 
including automated assessment, structured reporting, and risk prioritization. However, VulnScan 
differentiates itself by integrating an educational knowledge base, configurable vulnerability 
modules, centralized user management, and security audit logging while maintaining accessibility 
for educational and research purposes.

User feedback collected from official documentation, cybersecurity communities, industry

2.3 Research Gap  
The literature review indicates that numerous vulnerability assessment tools have been developed 
to identify security weaknesses within web applications. Open-source tools such as OWASP ZAP 
provide comprehensive automated vulnerability scanning, while Burp Suite Community Edition 
offers powerful manual security testing capabilities. Commercial solutions such as Acunetix 
further extend vulnerability management through enterprise reporting and workflow integration. 
Although these systems perform effectively within their intended domains, several research and 
practical gaps remain. 
 
Firstly, many existing vulnerability assessment tools primarily focus on identifying security 
vulnerabilities without providing sufficient educational support for users. Scan reports frequently 
contain technical terminology that may be difficult for students, beginner developers, and 
inexperienced security practitioners to interpret. As a result, users may identify vulnerabilities 
successfully but still lack sufficient understanding of their causes, impacts, and remediation 
techniques (OWASP Foundation, 2021). 
Secondly, many existing tools separate vulnerability detection from security knowledge. Users 
often need to consult external documentation, OWASP Cheat Sheets, or additional learning 
resources to understand detected vulnerabilities and implement appropriate secure coding 
practices. This fragmented learning process reduces the overall effectiveness of vulnerability 
assessment, particularly in educational environments. 
Thirdly, although several commercial vulnerability management platforms support centralized 
administration, these solutions are often associated with significant licensing costs that may limit 
accessibility for educational institutions and small organizations. Conversely, many open-source 
solutions provide extensive scanning functionality but lack integrated features such as 
configurable scan profiles, centralized vulnerability management, role-based administration, and 
comprehensive security audit logging. 
 

 
Finally, many existing systems are designed primarily for experienced cybersecurity 
professionals. Their interfaces, configuration options, and technical reporting may present a 
significant learning curve for users with limited cybersecurity experience. Consequently, there 
remains a need for a user-friendly vulnerability assessment platform that combines effective 
vulnerability detection with educational guidance and centralized management capabilities. 
To address these identified gaps, this project proposes VulnScan, an intelligent web application 
vulnerability assessment platform that integrates automated vulnerability assessment, 
configurable scan profiles, centralized user management, comprehensive audit logging, risk 
assessment, and an integrated vulnerability knowledge base within a single web-based 
application. By combining technical vulnerability assessment with educational support, the 
proposed system aims to improve both application security and cybersecurity learning outcomes.

3.1 Project Methodology 
The success of a software development project depends not only on technical implementation but 
also on the selection of an appropriate development methodology. A suitable methodology 
provides a structured framework that guides project planning, requirements analysis, system 
design, implementation, testing, and evaluation while ensuring that project objectives are 
achieved within the available time and resource constraints (Pressman & Maxim, 2020). 
For the development of VulnScan, the Agile Software Development Methodology was selected. 
Agile is an iterative and incremental software development methodology that emphasizes 
continuous planning, collaboration, adaptability, and regular delivery of functional software. 
Unlike traditional linear methodologies such as the Waterfall model, Agile allows project 
requirements and system functionalities to evolve throughout the development lifecycle based on 
continuous evaluation and feedback (Sommerville, 2016). 
 

 
The selection of Agile is particularly suitable for the development of VulnScan because 
cybersecurity applications frequently require continuous refinement as new security requirements, 
vulnerability detection techniques, and implementation challenges emerge during development. 
The modular nature of the proposed system also aligns well with Agile's iterative philosophy, 
allowing individual system modules to be designed, implemented, tested, and improved 
independently before being integrated into the complete system. 
Furthermore, the project consists of several interconnected modules, including user 
authentication, vulnerability management, configurable scan profiles, web crawling, vulnerability 
detection, risk assessment, audit logging, and the remediation knowledge base. Developing these 
modules incrementally reduces development complexity while enabling each component to be 
evaluated and improved before proceeding to subsequent iterations. This approach minimizes 
implementation risks and allows design improvements to be incorporated without significantly 
affecting completed components. 
Another important advantage of Agile is its flexibility in accommodating changes throughout the 
project lifecycle. During the design phase of VulnScan, several architectural improvements were 
introduced through iterative discussions and evaluations. For example, the original vulnerability 
configuration mechanism was redesigned into a more scalable ProfileModule architecture, 
enabling administrators to dynamically configure vulnerability modules without modifying the 
underlying database structure. Similarly, the database schema underwent several refinement 
cycles to achieve Third Normal Form (3NF), improve scalability, and eliminate data redundancy. 
These iterative refinements demonstrate the practical benefits of Agile in supporting continuous 
improvement while maintaining a stable and maintainable system architecture. 
In addition to improving software quality, Agile promotes continuous verification of project 
deliverables. Instead of postponing testing until the end of development, each completed module 
is reviewed, validated, and refined before progressing to the next development stage. This 
iterative verification process reduces the likelihood of major design flaws being discovered late in 
the project while improving overall software reliability and maintainability. 
Based on these considerations, Agile Software Development provides an appropriate 
methodological framework for the development of VulnScan. Its iterative, flexible, and modular 
approach supports the project's technical objectives while facilitating continuous improvement, 
efficient risk management, and systematic software development throughout the project lifecycle.

3.1.1 Planning Phase 
The Planning Phase is the first stage of the Agile software development methodology, where the

3.3.1 Analysis and Prioritization of Requirements  
After the system requirements were identified, they were analysed and prioritised according to

first before additional functionalities are implemented. 
The highest priority requirements include user authentication, role-based access control, 
vulnerability scanning, web crawling, scan result management, and vulnerability detection, as 
these modules form the core functionality of VulnScan. Supporting features such as the 
vulnerability knowledge base, scan profile management, and security audit logging are also 
important but are implemented after the core scanning functions have been established. This 
prioritisation enables the project to follow an iterative Agile development approach while

3.3.2 Identification of Dependencies and Conflicts among Requirements 
The identified system requirements were analysed to determine their dependencies and identify 
any potential conflicts before implementation. Understanding these relationships helps ensure that 
the system modules are developed in a logical sequence while reducing implementation risks. 
Several functional requirements depend on the successful completion of other modules. For 
example, users must be authenticated before performing vulnerability scans, and scan results can 
only be generated after the web crawling and vulnerability detection processes have been 
completed. Similarly, security audit logging depends on user authentication and system activities 
to record meaningful events throughout the application's operation.

non-functional requirements require careful consideration during development. For instance, 
increasing the depth of web crawling may improve vulnerability detection coverage but can also 
increase scanning time and system resource consumption. Therefore, configurable scan profiles 
are introduced to allow users to balance scanning accuracy and performance according to their 
requirements.

4.1 Architecture Design 
 
Figure 4.1: Overall System Architecture of VulnScan 

 
The overall architecture of VulnScan is designed using a layered architecture to separate system 
responsibilities into distinct layers, thereby improving maintainability, scalability, and modularity. 
As illustrated in Figure 4.1, the system consists of five primary layers: the Presentation Layer, 
API Layer, Business Logic Layer, Scanner Engine Layer, and Data Layer. Each layer 
performs a specific function while interacting with adjacent layers through well-defined 
interfaces, reducing coupling between system components and simplifying future maintenance 
(Pressman & Maxim, 2020). 
The Presentation Layer provides separate interfaces for Developers and Administrators through 
a web application. Developers are able to initiate vulnerability scans, review scan results, and 
manage scan profiles, whereas Administrators perform system management tasks such as user 
administration, vulnerability management, and monitoring system activities. User requests are 
forwarded to the API Layer, where the Flask REST API processes incoming requests and 
coordinates communication between the user interface and the backend services. 
The Business Logic Layer contains the core application modules responsible for implementing 
the business rules of the system. These modules include Authentication, Scan Management, Scan 
Profile Management, Vulnerability Management, and Audit Logging. The Business Logic Layer 
validates user requests, applies access control, manages application data, and coordinates 
interactions with the Scanner Engine. 
The Scanner Engine Layer is responsible for performing vulnerability assessments on target 
web applications. It consists of a Web Crawler and multiple independent vulnerability detection 
modules, including SQL Injection, Cross-Site Scripting (XSS), and HTTP Security Header 
analysis. The modular design enables additional vulnerability detection modules, such as 
Cross-Site Request Forgery (CSRF), XML External Entity (XXE), Server-Side Request Forgery 
(SSRF), and Command Injection, to be incorporated in future versions without requiring 
significant modifications to the overall system architecture. 
The Data Layer utilises Microsoft SQL Server to manage application data, including user 
accounts, scan information, vulnerability definitions, scan profiles, findings, discovered pages, 
and security audit logs. This layered architecture promotes separation of concerns, facilitates 
future system enhancements, and ensures that each system component can be developed, tested, 
and maintained independently. 
 
 
 
 

 
4.2 Database Design 
The database is designed to provide a structured and reliable repository for managing user 
information, scan configurations, vulnerability definitions, scan results, and system activities. 
Microsoft SQL Server was selected as the database management system because of its robustness, 
transactional reliability, advanced security features, and seamless integration with SQLAlchemy. 
These capabilities make it suitable for managing the relational data required by VulnScan while 
supporting future scalability and maintenance. 
The database design follows the principles of relational database modelling and has been 
normalised to Third Normal Form (3NF) to minimise data redundancy and maintain data 
consistency. Related data are separated into individual entities, with relationships established 
through primary and foreign keys to preserve referential integrity. This approach improves data 
organisation, simplifies maintenance, and reduces the risk of update anomalies. 
As illustrated in Figure 4.2, the VulnScan database consists of eight entities: User, Scan, 
ScanProfile, ProfileModule, Vulnerability, DiscoveredPage, Finding, and SecurityAuditLog. Each 
entity is responsible for storing a specific category of information required by the system. The 
relationships among these entities enable the system to manage vulnerability scanning activities, 
configurable scan profiles, modular vulnerability definitions, detected findings, discovered web 
pages, and security audit records while maintaining consistency across the database. 
The User entity manages user accounts, authentication information, and user roles, providing the 
foundation for role-based access control. The Scan entity stores information relating to each 
vulnerability assessment session and acts as the central entity connecting scan profiles, discovered 
pages, and detected findings. During execution, the Web Crawler records discovered web pages in 
the DiscoveredPage entity, while identified vulnerabilities are stored within the Finding entity and 
linked to the corresponding vulnerability definitions maintained in the Vulnerability entity. 
To improve flexibility and future scalability, VulnScan adopts a configurable scan profile 
mechanism through the ScanProfile and ProfileModule entities. Rather than hardcoding supported 
vulnerabilities within the application, administrators can configure which vulnerability detection 
modules belong to each scan profile. This modular approach allows future detection modules, 
such as Cross-Site Request Forgery (CSRF), XML External Entity (XXE), Server-Side Request 
Forgery (SSRF), and Command Injection, to be incorporated without redesigning the database 
structure. 
Finally, the SecurityAuditLog entity records significant user and system activities throughout the 
application. Maintaining audit records enhances accountability, supports security monitoring, and 
facilitates future forensic analysis by preserving a history of important events performed within 
the system.

4.3 User Interface Design 
The user interface of VulnScan is designed to provide a simple, consistent, and intuitive 
experience for both Developers and Administrators. The interface emphasises usability by 
presenting system functions in a clear and organised manner, allowing users to perform 
vulnerability scanning and system administration with minimal complexity. Consistent layouts, 
navigation menus, and interface components are adopted throughout the system to improve user 
experience and reduce the learning curve. 
The system provides separate interfaces based on user roles. After successful authentication, 
Developers are redirected to the Developer Dashboard, where they can manage scan profiles, 
initiate vulnerability scans, monitor scan progress, and review previous scan results. 
Administrators are redirected to the Administrator Dashboard, which provides additional 
functions such as user management, vulnerability management, scan profile configuration, and 
security audit log monitoring. This separation ensures that users only have access to functions 
relevant to their assigned roles. 
The Login Page serves as the entry point to the system by allowing registered users to 
authenticate using their credentials. Upon successful login, users are redirected to the appropriate 
dashboard according to their assigned role. If authentication fails, appropriate error messages are 
displayed to guide users while preventing unauthorised access. 
The Scan Management Page enables developers to configure and execute vulnerability scans by 
specifying the target URL and selecting a predefined scan profile. After the scan is completed, the 
Scan Result Page presents the detected vulnerabilities together with their severity level, affected 
pages, supporting evidence, and recommended remediation. The Administrator Dashboard 
provides management functions for maintaining users, vulnerabilities, scan profiles, and security 
audit logs, allowing administrators to oversee the overall operation of the system. 
Overall, the user interface design focuses on usability, consistency, and accessibility to ensure that 
both developers and administrators can efficiently perform their respective tasks while interacting 
with VulnScan.

4.4 Detailed Design 
4.4.1 User Authentication Process 
The user authentication process ensures that only authorised users can access the VulnScan 
platform. When a user submits their login credentials, the request is forwarded to the Flask REST 
API, where the credentials are validated against the information stored in the User entity. 
Passwords are verified using secure hashing techniques to protect user credentials during 
authentication. 
Upon successful authentication, the system generates a JSON Web Token (JWT) that is returned 
to the client. The JWT is included in subsequent requests to verify the user's identity and assigned 
role. Based on the authenticated role, the system redirects the user to either the Developer 
Dashboard or the Administrator Dashboard, ensuring that users only access functions relevant to 
their responsibilities. Failed authentication attempts are recorded in the SecurityAuditLog to 
support system monitoring and security auditing. 
 
 
 
 

 
Figure 4.7: User Authentication Activity Diagram 
Purpose: 
This workflow illustrates the authentication process performed when a user logs into VulnScan. It 
shows how login credentials are validated, how the system verifies the user's account status 
against the database, generates a JSON Web Token (JWT) upon successful authentication, and 
redirects the user to the appropriate dashboard based on their assigned role, while failed 
authentication attempts result in an error response.  
 
 
 
 
 
 
 
 
 
 
 
 

 
4.4.2 Vulnerability Scanning Process 
The vulnerability scanning process begins when a developer creates a new scan by providing a 
target website URL and selecting an appropriate scan profile. The selected scan profile 
determines which vulnerability detection modules will be executed during the assessment. 
The Scanner Engine first activates the Web Crawler to discover accessible pages within the target 
website. The discovered pages are recorded in the DiscoveredPage entity before being analysed 
by the enabled vulnerability detection modules. During the current implementation, the Scanner 
Engine supports SQL Injection (SQLi), Cross-Site Scripting (XSS), and HTTP Security Header 
analysis. Any identified vulnerabilities are stored as findings together with their severity, affected 
location, supporting evidence, and remediation recommendations. 
After the scanning process is completed, the scan status is updated and the results are presented to 
the user through the Scan Result interface. The modular design of the Scanner Engine allows 
additional vulnerability detection modules to be incorporated in future versions without 
modifying the overall system architecture. 
 
 
 
 

 
 
Figure 4.8: Vulnerability Scanning Activity Diagram  
Purpose: 
This activity diagram illustrates the end-to-end vulnerability scanning process performed by 
VulnScan. It shows how a developer initiates a scan, how the system validates the request, 
executes the configured vulnerability detection modules through the scanner engine, stores the 
scan results in the database, updates the scan status, and finally presents the findings to the user 
for analysis and reporting.  
 
 
 
 
 
 
 

 
4.4.3 Security Audit Logging Process 
To improve system accountability and security monitoring, VulnScan records important user and 
system activities using the SecurityAuditLog entity. Whenever significant events occur, such as 
user authentication, scan creation, vulnerability management, or administrative operations, the 
Business Logic Layer automatically generates audit records containing the event description, 
event time, responsible user, and related system information. 
The audit logging mechanism enables administrators to monitor system activities, investigate 
security incidents, and maintain a historical record of important operations. Centralising these 
records also supports future maintenance and forensic analysis by providing a complete history of 
significant events performed within the application.
