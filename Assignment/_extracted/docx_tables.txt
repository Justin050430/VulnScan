[473][Heading 2] 4.4 Detailed Design
[474][Heading 3] 4.4.1 User Authentication Process
[475][normal] The user authentication process ensures that only authorised users can access the VulnScan platform. When a user submits their login credentials, the request is forwarded to the Flask REST API, where the credentials are validated against the information stored in the User entity. Passwords are verified using secure hashing techniques to protect user credentials during authentication.
[476][normal] Upon successful authentication, the system generates a JSON Web Token (JWT) that is returned to the client. The JWT is included in subsequent requests to verify the user's identity and assigned role. Based on the authenticated role, the system redirects the user to either the Developer Dashboard or the Administrator Dashboard, ensuring that users only access functions relevant to their responsibilities. Failed authentication attempts are recorded in the SecurityAuditLog to support system monitoring and security auditing.

[496][Heading 3] 4.4.2 Vulnerability Scanning Process
[497][normal] The vulnerability scanning process begins when a developer creates a new scan by providing a target website URL and selecting an appropriate scan profile. The selected scan profile determines which vulnerability detection modules will be executed during the assessment.
[498][normal] The Scanner Engine first activates the Web Crawler to discover accessible pages within the target website. The discovered pages are recorded in the DiscoveredPage entity before being analysed by the enabled vulnerability detection modules. During the current implementation, the Scanner Engine supports SQL Injection (SQLi), Cross-Site Scripting (XSS), and HTTP Security Header analysis. Any identified vulnerabilities are stored as findings together with their severity, affected location, supporting evidence, and remediation recommendations.
[499][normal] After the scanning process is completed, the scan status is updated and the results are presented to the user through the Scan Result interface. The modular design of the Scanner Engine allows additional vulnerability detection modules to be incorporated in future versions without modifying the overall system architecture.

[515][Heading 3] 4.4.3 Security Audit Logging Process
[516][normal] To improve system accountability and security monitoring, VulnScan records important user and system activities using the SecurityAuditLog entity. Whenever significant events occur, such as user authentication, scan creation, vulnerability management, or administrative operations, the Business Logic Layer automatically generates audit records containing the event description, event time, responsible user, and related system information.
[517][normal] The audit logging mechanism enables administrators to monitor system activities, investigate security incidents, and maintain a historical record of important operations. Centralising these records also supports future maintenance and forensic analysis by providing a complete history of significant events performed within the application.

[529][Heading 2] 4.5 Chapter Summary and Evaluation
[530][normal] This chapter presented the overall system design of VulnScan, which serves as the blueprint for the implementation of the proposed web application vulnerability assessment platform. The design was developed based on the functional and non-functional requirements identified in Chapter 3, ensuring that the proposed system architecture satisfies the project's objectives while supporting maintainability, scalability, and security.
[531][normal] The chapter first described the overall system architecture, illustrating how the Presentation Layer, API Layer, Business Logic Layer, Scanner Engine, and Data Layer interact to provide the core functionalities of VulnScan. It then presented the database design, including the Entity Relationship Diagram (ERD) and the purpose of each database entity. The user interface design was subsequently discussed to demonstrate how Developers and Administrators interact with the system through a consistent and user-friendly interface. Finally, the detailed design explained the major system processes, including user authentication, vulnerability scanning, and security audit logging.
[532][normal] Overall, the proposed system design provides a structured and modular foundation for implementing VulnScan. The design decisions presented in this chapter support future system enhancements while ensuring that the application remains maintainable and extensible. The next chapter describes the implementation of the proposed system based on the designs presented in this chapter.
